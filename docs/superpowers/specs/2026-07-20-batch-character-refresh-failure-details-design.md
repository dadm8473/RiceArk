# 캐릭터 일괄 갱신 실패 상세 표시 설계

## 배경

표의 캐릭터 정보 일괄 업데이트 API는 각 캐릭터에 대해 성공 여부와 실패 상태를 이미 반환한다. 현재 웹은 성공 결과만 적용하고 실패 결과는 개수로만 집계하므로, 사용자는 어떤 캐릭터가 왜 실패했는지 알 수 없다.

## 목표

- 일괄 업데이트 결과에 실패한 캐릭터 이름과 한국어 실패 사유를 표시한다.
- 기존 배치 응답만 사용하고 추가 API 요청을 만들지 않는다.
- 성공한 캐릭터 갱신과 기존 최대 40명 제한 동작은 그대로 유지한다.
- 실패가 여러 건이어도 업데이트 모달의 전체 레이아웃을 과도하게 늘리지 않는다.

## 사용자 경험

업데이트가 일부 실패하면 기존 요약 문구 아래에 실패 목록을 표시한다.

```text
12명 업데이트, 3명 실패했습니다.

냠수나이스1  1분 뒤 다시 시도해주세요.
펄쩍수빈      로스트아크에서 캐릭터 정보를 찾지 못했습니다.
반짝수빈      일시적인 API 오류입니다.
```

- 각 항목은 캐릭터 이름과 사유를 한 행으로 보여준다.
- 목록은 업데이트 패널 안에 표시하고 최대 높이를 둬서 긴 목록만 내부 스크롤한다.
- 별도의 항목별 재시도 버튼은 추가하지 않는다. 기존 업데이트 버튼으로 전체를 다시 시도한다.
- 성공만 있으면 기존 `N명 업데이트 완료` 문구만 표시한다.
- 요청 자체가 실패하면 기존 일반 오류 문구를 유지한다.

## 데이터 흐름

1. `refreshBoardTableCharactersRequest`가 배치 응답의 성공 항목을 기존처럼 보드에 적용한다.
2. 성공이 아닌 항목은 `id`, 원본 `status`, 필요한 부가 정보로 실패 상세 목록에 보존한다.
3. 표의 축 항목에서 캐릭터 ID별 표시 이름을 구성해 실패 상세와 결합한다.
4. `TableCharacterRefreshSummary`가 성공·실패 개수와 함께 실패 상세 배열을 모달에 전달한다.
5. `BoardTableToolModal`이 요약 문구와 실패 목록을 렌더링한다.

동일 캐릭터가 표에 여러 번 참조되어도 배치 요청 단계에서 ID가 중복 제거되므로 실패 항목은 한 번만 표시한다. 이름을 찾지 못하는 예외 상황에서는 `알 수 없는 캐릭터` 대신 ID를 사용해 식별 가능성을 유지한다.

## 실패 사유 매핑

- `rate_limited`: 응답의 남은 초를 사용해 `N초 뒤 다시 시도해주세요.`
- `not_available`: `로스트아크에서 캐릭터 정보를 찾지 못했습니다.`
- `not_found`: `저장된 캐릭터를 찾을 수 없습니다.`
- `manual`: `수동 캐릭터는 자동 갱신할 수 없습니다.`
- `failed`: 내부 오류 코드는 노출하지 않고 `일시적인 API 오류입니다.`

현재 표 일괄 갱신 대상은 가져온 캐릭터만 수집하지만, 서버 경쟁 상태나 데이터 변경으로 다른 상태가 돌아올 수 있으므로 모든 상태를 사용자 문구로 처리한다.

## 서버 부하

서버와 API 응답 형식은 변경하지 않는다. 이미 내려온 실패 결과와 현재 보드의 캐릭터 이름을 클라이언트에서 조합하므로 추가 네트워크 요청, D1 조회, 캐시 무효화는 없다.

## 검증

- 성공과 모든 실패 상태가 섞인 응답에서 실패 상세가 순서대로 보존되는지 테스트한다.
- 캐릭터 ID가 표의 이름과 올바르게 결합되는지 테스트한다.
- 각 실패 상태가 적절한 한국어 사유로 변환되는지 테스트한다.
- 모달이 요약과 실패 목록을 함께 렌더링하는지 테스트한다.
- 성공 전용, 40명 제한, 요청 자체 실패의 기존 동작이 유지되는지 회귀 테스트한다.
- 데스크톱과 모바일에서 목록의 줄바꿈, 스크롤, 겹침을 시각 검증한다.

## 배포 및 패치노트

전체 검사와 빌드 후 메인에 반영하고 운영 배포한다. 운영 패치노트에는 앞서 배포된 캐릭터 레벨·전투력 개별 잠금 기능과 이번 일괄 갱신 실패 상세 표시를 함께 안내한다.
